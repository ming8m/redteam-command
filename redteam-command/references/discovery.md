# 从业务事实选择调查方向

首次建立路线、遇到新的业务能力或原路线停滞时使用。方向来自实际页面动作、正常请求、匹配源码和授权方材料；不把产品名称或漏洞列表当作入口证据。实验和结论继续遵守 [推理规则](reasoning.md)，技术机制按需进入 [高影响调查](high-impact.md)。

## 先说明哪条约束可能失守

写清操作发起者、实际执行者、对象所属方、允许动作、有效状态和结果使用者。事实绑定出处，缺项标为未知。然后问：哪次交接依赖了前一层的检查；哪个替代入口、重试或结果消费者可能没有收到同样的条件？

从现有信号选择一个有判别力的变化，其他条件固定：

- 出现代理、后台作业或连接器：核对发起身份在执行与结果读取处是否仍有效，服务身份的能力是否被误当作用户许可。
- 出现批量、预览、下载或旧版本：核对同一对象的读取、字段可见性和动作许可是否一致；相同界面不足以复用后端结论。
- 出现审核、撤回、转移或恢复：先确定规则采用哪个时刻的身份和状态，再观察状态变化后的实际效果。
- 出现缓存、重试或多消费者：核对隔离键、幂等规则和各消费者的解释方式；同值或不同响应都可能符合契约。
- 出现查询、转换、模板或任务执行：先追踪受控输入实际到达的位置，再选择能证明查询语义、服务端执行或关键权限变化的实验。

多个方向竞争时，优先补能决定路线是否成立的前提，兼顾影响、区分力、观察能力和代价。没有异常但有未经检查的真实交接点，可以做有限探索；没有可用观察则先恢复观察条件。

## 每条假设的六项记录

使用案件附件，按 [结论附件格式](claim-format.md) 记录；这些是解释实验的字段，不是第二套任务状态。

1. **应维持的约束**（`hypothesis.constraint`）：谁在什么条件下能够对哪个对象做什么，规则的事实依据在哪里。
2. **疑似失守的位置**（`failure_boundary`）：具体路由、调用交接或最终消费者，输入如何到达它；观察与推测分别写。
3. **最小可见结果**（`minimal_observation`）：改变一个条件后，哪项字段、读回状态、服务端记录或受控效果能区分两种解释。
4. **阴性对照设计**（`negative_control`）：条件合法或保护生效时应看到什么，为什么该对照与测试对象、身份和时间可比较。
5. **可推翻假设的结果**（`falsifier`）：哪项结果能排除当前解释，排除的身份、版本与环境范围有多大。
6. **确认需要的材料**（`evidence_threshold`）：支持突破和业务影响所需的基线、对照、关联与复核证据；潜在扩展另列。

以上字段都位于 `hypothesis` 内，`refs` 指向支撑约束和实验设计的 evidence ID，其祖先须完整且 context 相容。最小观察描述拟观察的结果，不冒充尚未发生的实验；实验后的事实另外绑定 checks。

schema 2 候选补前提、报告或复核阶段允许六字段为 null；安排 probe 或拟交付 confirmed 时须六字段齐备并绑定引用。缺身份、入口或观测通道记录具体受阻前提。字段齐全不表示材料成立，confirmed 还要实际语义复核与独立的能力、对象、前提和定级依据。

阴性对照是实验安排，证伪条件是如何解释结果，两者不能互相替代。失败对照本身不支持成功主张；无法排除的反证必须保留，并限制最终标题和影响。

## 白盒与根因变体

固定审阅的提交或发布版本，沿入口、转换、检查、实际处理点与最终副作用核对调用链。危险函数、公开修复和版本相似性只提供调查线索；还要核对路由启用、运行配置、框架默认行为和攻击者可控制范围。

得到一个根因后，寻找实现同一约束的其他地方：单条与批量、正常与恢复、同步与后台、旧版本与修复版本。先比较实现差异及可达性，再决定哪些变体值得实验。共享了已验证保护层可以缩小重复工作，但只复用已比较的条件。

同一失败分支的计数遵守 reasoning.md，换编码、工具、执行者或入口名称不能重置。只有新事实改变必要前提，或有记录的有限继续要求与区分价值，才重开。修复后验证应覆盖原失败条件和一个合理反例，不为报告数量重复确认同一根因。

## 自创合成推演

以下是原创合成讨论案例，未执行结果不能写成实验结论，也不代表检出率提升。

### 报价比较页面与汇总视图

虚构采购系统允许供应商查看自己报价，比较页面给普通访客显示供应商名称和公开交期，采购角色另外看到未公开价格。

约束是保密价格仅向采购角色与报价所属供应商开放；疑点在汇总视图的字段投影。最小观察是在两份受控报价上核对普通身份实际获得的价格字段，阴性对照包括采购角色的完整视图与访客的公开视图。若差异仅为公开交期，或实际身份已获授权，当前假设被排除。确认材料必须证明报价归属、价格未公开、请求身份和返回的实际字段；仅看到两种页面外观不同不够。

### 定时报表复制后的执行身份

虚构能源分析平台允许测试租户复制自己的定时报表。复制功能与执行队列属于不同模块，执行记录保存发起租户。

约束是复制后的作业只处理复制者获准的数据；疑点在复制配置与队列身份交接。最小观察是受控作业最终生成内容及其租户关联，阴性对照是各测试租户自己的正常作业。若复制的是按契约共享的合成数据，结果相同不构成突破。只有作业完成、内容确属另一受控租户且权限不允许时，才具备确认基础；任务受理和一个作业 ID 都不足以证明执行影响。

### 设备备件预留的恢复动作

虚构维修演练系统中，一张工单确认后预留一件合成备件；恢复动作应保留同一预留记录，重试不能再次增加数量。

约束是一次确认只产生一份预留；疑点在失败恢复路径是否沿用幂等标识。最小观察是恢复后重新读取工单与预留计数，阴性对照是未失败的普通重试。若两次成功响应指向同一条预留记录，异常外观被排除；若计数存在已知异步窗口，先等待契约允许的收敛时间。确认需关联真实提交的两次副作用与相同业务事件，不把日志条数当作库存变化；使用隔离合成对象，验证后恢复初始状态。
