# 高影响路线：从真实业务请求到边界突破

用于已授权的 SQLi、服务端执行与身份接管评估。先恢复能够成功的正常业务请求，再把可控输入或身份状态映射到敏感操作，最后用最小对照验证因果。用户已给系统与漏洞类型时据此集中推进，不扩成无目标的端点扫描。

下述基线和动态对照用于当前复现；仅源码审计或历史证据审阅时，完成对应实现链或记录语义核对，明确其限制，不为取得动态标签擅自访问目标。

## 共同起点

1. **恢复请求契约。** 从真实业务页面、动态模块、接口定义、匹配源码或授权方脱敏请求取得路由、方法、编码、字段和身份传递方式。读取助手函数实现，不凭函数名猜 GET/POST；动态页面未获取时明确缺口。
2. **建立正常成功基线。** 用授权测试身份和合成对象完成一项正常操作，确认结果、对象归属及环境。请求 ID、脱敏请求、响应和时钟信息一起保存。业务校验失败、500 空体或拦截页不是正常基线。
3. **选决定性实验。** 写出要改变的唯一条件、有效正控制、负控制、竞争解释和执行见证。执行已有授权覆盖的最小验证；前提缺失时由 owner 补契约、身份、源码或日志，不重复猜字段。

两次同失败分支没有新信息后回到依赖恢复，规则见 [reasoning.md](reasoning.md)。有正常基线也不等于存在漏洞；它让后续差异可解释。

## SQLi：证明输入改变 SQL 语义

**先定位：** 请求契约 owner 给出真实输入字段及其对象/权限条件；机制 owner 追踪该值进入控制器、查询构造、绑定/转义处理和数据库调用的位置。黑盒只能得到部分链条时，列出缺边，利用授权可读的响应、日志或监控完成关联。数据库列名、搜索词相似或大量内联文本只能帮助定位，不能直接充当 HTTP 参数名。

**再验证：** 在同一业务、身份和对象下比较正常请求与最小语义对照。尽可能让请求 ID、目标方 SQL/应用日志或受控测试数据的差分互相印证；基于时间的实验保留预先约定的重复样本及非数据库因素对照，排除代理拦截、缓存和网络等待。不要由单次长延迟或 SQL 错误直接确认。

**交付四件事：**

- 请求字段到 SQL 语法位置的证据；说明是当前关联、匹配源码还是推测。
- 正常成功基线与正负控制的完整结果，证实输入影响了原本应固定的查询语义。
- 执行证据与失败证据分开：数据库执行统计、解析/拦截统计各说明其含义。
- 实际跨越的边界和最小影响，不需要真实个人数据、整库读取或写库来扩张结论。

**历史和源码的用途：** 历史 SQL 中无错误的条件差分可以是强执行证据，应优先追查；匹配源码中完整的未受保护数据流可以证明实现缺陷。报告分别标注历史观察、源码证明与当前复现。黑名单中的取数尝试、函数计数、数据库账号名称不能替代当前可利用性或实际取数证明。

## 服务端执行：证明目标执行了什么

**先核原语：** 从匹配实现确认入口最终调用的是系统命令、解释器、模板编译/写入、反序列化还是管理操作；记录版本来源与配置前提。官方上游源码与目标版本尚未对应时，把该差异列为待验证。类名、扫描标签、健康检查布尔值不证明任意代码执行。

**逐层确认：** 对照正常入口与目标操作，判断请求是否通过认证、来源限制、配置开关和参数检查。403 记录为本次被拒及所处阶段；不要凭同一结果扩大为所有路径可利用或永远不可利用。

**取得执行见证：** 选择已有授权覆盖、可恢复的最小验证，使用与本次请求可关联的目标端结果、日志或遥测。见证要能排除请求回显、路径错误文本、预置响应和本地工具输出，并说明执行位置及进程身份。只有隔离环境实验时，结论限于该环境。

**交付四件事：**

- 外部输入到执行原语的链路，以及已通过/未通过的检查。
- 正常基线、负控制、实验结果和目标端执行见证。
- 可证实的运行主体与能力；把模板动作、命令执行和主机接管分别表述。
- 实际副作用、恢复与清理证据。

默认使用临时、最小、可恢复的验证；不默认持久化 webshell、建立驻留或扩大到其他资产。此类扩大操作只有在用户明确目标与已有授权确实覆盖时另立任务，不作为证明一次执行的必要步骤。

## 身份接管：证明拿到谁的实际权限

**先恢复身份流：** 选择授权测试账号，记录登录、会话续期、找回、SSO 或凭据交换的正常过程。明确身份由哪一方证明、token/会话在哪里传递、后端采用哪个 guard/受众/校验来源，以及一项可确认当前主体的正常业务动作。

**再做身份对照：** 使用授权范围内的两个测试主体或明确的匿名/登录对照，保持业务动作与对象条件可比。追踪可控状态如何改变认证决定，再用最小受保护操作确认最终主体和权限；必要时由授权方提供日志佐证。令牌内容、用户编号、登录成功提示和 HTTP 200 本身不足以证明账号接管。

**交付四件事：**

- 起始身份、预期身份及被绕过的身份校验。
- 实际凭据传递契约与正常成功基线，凭据值使用受控存储引用。
- 主体/权限改变的正负控制与目标端证据，排除合法共享、错误 guard 和管理员原有权限。
- 会话、测试凭据或合成对象的恢复情况；不触碰未授权用户来扩大影响。

## 缺少前提时继续做什么

| 缺口 | owner 的下一项具体工作 | 当前可交付 |
|---|---|---|
| 有入口但请求始终失败 | 恢复真实页面模块、方法/编码与字段对象，核对目标方正常请求 | 失败位置、缺失契约、已排除解释 |
| 缺可用测试身份 | 读取已有授权材料和受控身份；恢复认证方式，向用户集中索取具体测试身份或脱敏成功请求 | 匿名侧已观测结果及身份依赖；不从 500 推断一定需登录 |
| 实现或版本不明 | 核对目标方依赖清单、源码、可证实指纹与官方实现差异 | 实现候选与会改变结论的版本/配置前提 |
| 当前被阻断但有历史证据 | 关联路由、时间和目标方日志，区分历史阶段与当前条件 | 强历史发现及当前未复现边界 |
| 仅允许离线工作 | 复算完整原始证据，审匹配源码及跨文件矛盾 | 离线结论与最小待补证据 |

授权足够且材料可用就行动，不用反复询问确认。缺口只限制依赖它的实验；其他已授权工作继续。最终交付应让用户分清：哪条高影响路径已证实、哪条被证伪、哪条停在什么前提，以及下一项工作为何能改变判断。
