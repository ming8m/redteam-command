# 决策、因果与证据

## 优先验证哪一条路径

用户指定目标与优先级优先。开展高影响评估时，优先研究有具体信号的 SQLi、服务端执行和身份接管；依据见 [高影响路线](high-impact.md)。严重性决定投入方向，证据决定结论强度，两者分别裁决。

主控维护少量当前主线，每条写清：要保护的边界、实际观察、必要前提、竞争解释、下一项可区分解释的实验、成立后的影响。优先补最薄弱且能决定整条路径的前提，结合信息价值、依赖解锁、成本和副作用排序，不编造概率分数。用户已指出系统和类型时，集中恢复该系统的正常请求与服务端去向。

目录、指纹、调试信息可以解锁后续工作，也可以独立交付；它们不能按数量替代尚未完成的高影响目标。结论为证伪或零个确认漏洞同样有效。

## 实验与停止规则

每个实验先写出正常基线、唯一要改变的条件、预期观察、竞争解释和证伪结果。优先使用授权测试身份与合成数据；已有授权覆盖的最小验证直接执行，需要变更时绑定恢复与清理办法。

同一失败分支两次没有新增信息后暂停该分支，交主控改做依赖恢复。同一分支按“缺失前提 + 所到达处理环节 + 结果类别”判断：几十个猜测字段均返回 500 空体仍是同一失败；换字段、工具或 Agent 不重置计数。预先设计的时序统计采样算一个实验，保留其样本与对照。

重开依据应是可引用的新事实，如真实字段对象、有效测试身份、匹配源码、目标方日志或变化的环境。暂停不等于放弃案件：继续已授权的客户端/源码/日志分析，集中询问真正阻塞的具体材料；不重复询问已明确的授权。

用户明确要求有限继续时，记录该要求、实验上限和区分价值；不能把继续要求当成新证据，也不能因预算仍有余额自动重开。

预算包含时间、请求数/速率、并发、工具成本和复核余量。出现范围外目标、环境异常或副作用超过约定时停止受影响动作、保留最少证据并汇报，其他独立工作继续。

## 区分三种证据方式

| 方式 | 可以支持的结论 | 必须保留的限制 |
|---|---|---|
| 当前实验 | 指定环境、身份与请求下观察到的因果结果和边界突破 | 未测试的其他身份、入口和扩展能力 |
| 源码证明 | 对匹配版本的完整调用链、检查与敏感操作的实现判断 | 部署适配、运行配置、外部可达性及未实测影响 |
| 历史观察 | 已记录的 SQL、日志或执行迹象及当时统计 | HTTP 来源、发起者、当时身份、时钟和当前可复现性 |

方式可相互补充，不能相互冒充。公开框架实现只是版本比对来源； SQL 列名不是 HTTP 字段；解析/拦截计数不等于执行成功；获得一个 token 不等于获得其声称的权限。先表述确实证实的命题，再单列潜在影响和必要前提。

每条路径边记录：`起始身份/状态 → 必要前提 → 已授权动作 → 实际结果`。给边绑定原始证据、时间、环境与版本；前一边实际产生的身份和能力必须满足后一边，不把不同账号、版本或时段的片段拼成已复现路径。

## 漏洞成立与严重性分别裁决

按四个问题逐项裁决，不把它们混成一次“确认”：观察是否真实；哪条安全约束已被突破；该突破的业务影响达到什么等级；目标平台是否收录。前三项需要各自的事实依据，最后一项需要实际规则，不能拿通用安全建议冒充SRC收录或定级标准。

中高危结论附短理由：起始权限、必要环境条件、可获得的具体能力、受影响数据/操作的敏感性与范围、对应证据、采用的定级规则或明确标注的技术初评。缺少关键影响依据时保留未定级候选，不用假设的后续攻击链抬高当前结果。

- HTTP页面、缺少安全头、产品指纹或debug开关可以是真实配置观察；一般性“可能被中间人修改”不能直接支撑本案中危。需要对应实际认证/数据链路、攻击前提和后果，再评价级别。
- 监控可读时先清点实际返回的数据。内网地址、库名、账号名称、表结构、SQL文本及其条数，不自动证明有效凭据或敏感业务内容泄露；不能仅凭“未授权”或“1000条”升级到中高危。若另有有效秘密、受保护业务数据或关键操作能力的证据，按该新增事实单独评估。
- 历史执行痕迹、令牌字符串和接口成功提示保留其事实意义；尚未证明当前输入、权限或状态变化时，不计作本轮已确认利用。
- 证明影响不要求窃取真实用户数据。匹配部署的完整源码证明、受控合成数据上的边界突破，以及有来源的服务端记录均可形成有效依据。不要把证据严谨性变成“必须实际造成损害”。

复核者要指出证据支持的具体命题和无法支持的扩展；多个Agent意见一致仍可能共同误读。结构预检、哈希、测试通过次数不能补上业务影响证明；等级判断须能由证据重新推导。

## 保留可复算的证据

- 原始请求/响应或实现位置带实验 ID、身份别名、时间与时区、环境、文件路径及 SHA-256；凭据仅用受控引用，不落明文。时钟未校准就分别记录，不能直接归因到同一窗口或某个发起者。
- 标明原始/派生、完整/截断。派生结论指向原始文件及 JSON 下标/ID、行号或其他稳定定位；超出截断范围的结论不能声称可从该原文复算。哈希只证明文件未变，不证明内容真实。
- 保留正常成功基线、负控制和异常结果；失败请求同样有价值。200、500、长度或哈希用于描述观察，不能单独确定认证、权限或执行行为。
- 验证到授权范围内的边界突破即停止无助于结论的扩大操作；记录实际副作用、恢复结果与遗留项。

## 独立复核与交付

复核者先从原始证据判断，再比较作者解释。注明“离线审阅”“源码复核”或“独立实验”；独立重放须有另一执行者的真实实验记录，其路由、身份和命题对应。多个摘要和同一执行者换工具不构成多份独立证据。

主控处理无法消除的分歧时保留未知，并给最小补充证据。对会被前一实验改变的对象，换合成对象或核对状态，避免把污染后的结果当复现。

用身份—对象—动作—状态的已验证单元报告覆盖，把限制有效、缺陷成立、未完成、前提缺失和合理不适用分别说明，再映射到调用方任务系统实际支持的结构。账号缺失、预算耗尽和入口不可达属于限制，不改成不适用求通过。

报告摘要、专项说明和最终裁决应引用同一证据版本；强影响主张分别绑定证明，未知项留在正文和摘要中。`check_claim.py` 仅做附件预检，不替代独立判断或调用方的完成验收；通过预检不等于漏洞成立。
