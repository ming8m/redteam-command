# 按问题组织高影响验证

围绕最有依据的边界突破分工。SQLi、服务端执行、身份接管的具体推进见 [高影响路线](high-impact.md)；证据与停止规则见 [推理与证据](reasoning.md)。角色是责任，不要求一人一进程。

维护与仅离线工作先继承入口的工作方式：分配文档、源码、附件结构和工程行为问题，不把角色名称当主动验证任务。无漏洞验证的限制同时写入原始简报与后续交接，不能通过横向协查、换执行者或 Hub 衍生任务解除。

## 责任与可验收交付

| 角色 | 要回答的问题 | 应交付 |
|---|---|---|
| 主控 | 用户目标是什么；先补哪个前提最可能确认或否定高影响路径 | 当前主线、排序理由、预算、依赖、裁决及最终报告 |
| 请求契约 owner | 谁通过哪个真实请求完成正常业务；候选输入在哪里 | 方法/编码/字段/身份传递方式、正常成功基线、客户端或接口来源、未恢复的动态模块 |
| 机制 owner | 输入如何到达数据库、执行能力或身份边界 | 输入到敏感操作的映射、实现与版本来源、检查发生的位置、最小因果实验及见证 |
| 反证 reviewer | 哪个竞争解释仍能解释结果；引用能否复算 | 原始证据审阅、有效对照、支持/反驳/无法判定；注明是离线复核还是独立实验 |
| 业务域组长（可选） | 一个域内如何拆成互不冲突的验证 | 有 owner 的子任务、域内汇总、跨域依赖和预算使用情况 |

资产、身份和业务知识按问题分配给上述 owner：资产发现服务于入口归属和依赖解锁；身份专家恢复真实权限条件；业务专家定义应保持的不变量。需要专门调查时再派一项明确子任务，不按漏洞目录创建常驻小组。

## 编排与汇合

**单业务域：** 主控负责路径分析，请求契约与机制调查可并行，给反证复核保留名额。正常请求尚未恢复时，机制 owner 可读匹配源码或日志；涉及该请求的实验等待前提成立。

**多业务域：** 每域确有独立工作和预算时设组长。主控保留跨域身份依赖与最终裁决；最多主控→组长→执行者。运行时不能嵌套派工时，组长出简报、主控实际派发。

在以下节点汇合，交付能让下一 owner 开始工作的材料：

1. **契约恢复：** 给出正常请求、参数来源、身份别名和响应；未成功时交缺口，不能拿一批同样的 500 代替。
2. **机制定位：** 给出输入到敏感操作的每条边，以及哪条来自源码、哪条来自当前实验、哪条只是历史迹象。
3. **因果验证：** 执行已有授权覆盖的最小实验，交付正负控制、目标端见证和实际影响；授权充分就继续，不重复申请批准。
4. **独立裁决：** reviewer 先看原始证据再看作者解释。主控按证据处理分歧，补齐最薄弱前提后再决定确认或转向。

每项任务只有一个 owner。按资产、身份、业务动作、假设、环境/版本去重；同一对象的变更、共享账号及共享限额动作串行。同一证据的多次转述不算独立验证。

方向形成后先按 [discovery.md](discovery.md) 写出可证伪假设，再把必要前提连到实际任务 ID。主控先用约束、处理点、身份/对象/状态和环境判断重复，模糊相似交复核者；不能把模型一句“不同”当成唯一去重门禁。同根因多入口作为变体引用，新增影响或不同根因再单独立发现。

执行者交 [动作附件](../assets/action-record.md)，让工具调用、返回与目标效果可分别核对。续接与失败恢复按 [execution.md](execution.md) 操作；这些附件只是证据和快照，不另存运行状态。实际派工前必须查最新任务记录与前置交付，旧摘要和任务 closed 不能代替实验前提。

## 横向协查

消息只携带能改变对方判断的信息，格式可采用：

```text
案件标识 / task_id / parent_task_id / sender / recipient:
相关命题及消息用途: 新证据 / 补缺口 / 反证 / 依赖阻塞
事实与来源: 原始附件、SHA-256、时间、身份别名、版本
解释与未知: 与观察分开
希望对方回答的问题 / 期限:
需要新增动作或预算: 有则交共同上级登记
```

这些是消息语义，不是新增 API 枚举。同级可分享证据和提出协查，不能修改对方 owner、授权或完成状态。明文凭据只通过既定受控方式使用，不进入消息。

## 失败、交接与状态

- 同一失败分支两次无新增信息后回到主控；换 Agent、工具或猜测字段不自动获得新预算。重开要带改变前提的证据，具体规则见 reasoning.md。
- 交接前核实原执行者已停止、现有附件和副作用；租约过期不等于进程停止。通过调用方支持的 owner/租约流程交接；没有租约能力时明确记录接管并核实原执行者停止。
- 专家各写自己的附件，主控通过实际可用的任务接口汇总；冲突先对齐版本、时钟、身份和对照，不按多数票确认。
- 撤销、受阻、未复现均保存原因和产出，使用调用方系统实际支持的状态。独立离线审阅不能签成独立重放；后者必须关联另一执行者的实验记录。

向用户汇报新事实、判断变化、下一项决定性工作。高影响分支未完成时直说缺口，不用低影响发现数量冲抵目标。
